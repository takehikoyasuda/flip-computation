```
git clone git@github.com:takehikoyasuda/flip-computation.git
cd flip-computation
M2 --script tests/run-tests.m2      # "all tests passed" が出れば OK
```

Homebrew の `icu4c` が 78 に上がると `libicudata.74.dylib not found` で起動しなく

```
mkdir -p /opt/homebrew/lib/Macaulay2/lib
for f in libicudata.74.dylib libicui18n.74.dylib libicuuc.74.dylib; do
  ln -sf /opt/homebrew/Cellar/icu4c/74.2/lib/$f /opt/homebrew/lib/Macaulay2/lib/$f
done
```

## 3. 作業 A: 局所（アフィン）版サポートとトーリック例での検証

### A-1, A-2 は完了

実装は roadmap の当初案どおり（`baseIsProjective` キー、次元補正の切り替え、
`BaseIsProjective` オプション、`isSmallProjection` は共通のまま）。実際に書いてみて
分かった点だけ記す。

* アフィンの場合、`k[u,x]` に `deg x_j = 0` を入れると heft ベクトルが取れず
  `basis` などが壊れる。u 次数付けは**明示せず**、標準次数の環で計算している。
  実際に使う操作（gb, `eliminate`, `minimalPrimes`, `dim`, `isNormal`）はいずれも
  次数付けを必要としないので問題ない。
* `b2mToGraphMorphism` はアフィンでは意味を持たない（Lemma 2.3 の Segre 構成が
  両方の次数付けを要る）ので明示的にエラーにした。
* `canonicalDivisorData` / `antiCanonicalSection` / `flipDivisorData` にも
  `BaseIsProjective` を通した（`Divisor` の `IsGraded` に渡すだけ）。
* パッケージ本体の `load "FlipComputation/basics.m2"` が相対パスだったため、
  `check` がサブプロセスでテストを走らせるとファイルが見つからず落ちていた。
  `currentFileDirectory` 基準に修正済み。
* TEST ブロックからは `PackageImports` の `Divisor` のシンボル（`canonicalDivisor`,
  `divisor`）が見えない（`Polyhedra` のものは見える）。テストではパッケージ自身の
  `canonicalDivisorData` を使い、線形同値の確認は `examples/toric-flip.m2` 側で
  `needsPackage "Divisor"` して行っている。

検証結果（`examples/toric-flip.m2`、実行約 0.7 秒）:

* `K_X` は `-D_1 - D_3` として返る。トーリックな `-Σ D_i` とは主因子
  `div(y_1) = D_2 + D_4` の分だけ違い、線形同値であることを確認した。
  当初「`-Σ D_i` になるはず」と書いたが、`Divisor` パッケージが返すのは
  標準加群から作った代表元なので一致する必要はない。
* `s = 1`, `E = D_1 + D_3`, `I = O_X(-E)` の生成元はちょうど2個。したがって
  Z ⊂ P^1 × X で、これは Z の極大錐の個数と一致する。
* **m = 1 で通る**（正規かつ small）。
* トーラス固定点上のファイバーは1次元 → 例外集合は曲線。
* 2つのチャートはいずれも3次元で smooth。I の生成元から復元した扇は
  `<v1,v3,v4>, <v2,v3,v4>` に一致。壁 `<v3,v4>` での wall relation から
  `K·C = +1 > 0`、すなわち K_Z は π-ample。反対側 Y では `K·C = -1 < 0`。
  つまり `computeFlip` はフリップを返しており、入力側の縮約ではない。

### A-3 は完了: 射影版

`examples/toric-flip-projective.m2`。X_aff の Hilbert 基底はすべて
`ℓ = (1,1,-1)` で次数1なので標準次数がトーラス指標から来る。よって

```
X_proj = Proj k[y_1..y_5, w]/I  ⊂ P^5,  deg w = 1
```

は3次元で `D_+(w) = Spec R = X_aff`。変数の増加は予定どおり1個。

**「頂点以外にも特異点が出る」という懸念は外れた。** X_proj もトーリックで、
τ = σ × R≥0 の生成線を v = (1,1,-1,1) で射影すると
`u1=(1,0,0), u2=(0,1,0), u3=(0,0,1), u4=(1,1,-2), u5=(-1,-1,1)`、極大錐は
`<u1,u2,u3,u4>`（= σ = D_+(w)）と σ の4つの facet を u5 と結んだもの。後者は
すべて行列式 ±1 なので、**X_proj の特異点は頂点ただ一つ**でフリップしたい点そのもの。
σ を貼り替えても6錐すべて滑らかなので、フリップは滑らかな射影トーリック3-fold。

検証結果（1.5 秒）:

* m = 1 で成功。`I = (y_1^2 y_5, y_1^2 y_4)` はアフィン版の `(y_5, y_4)` の
  主因子倍で、ブローアップは同じ（`Bl_{fJ} X = Bl_J X`）。この因子は K_X の
  代表元の取り方から来る。
* 頂点上のファイバーは曲線。
* Z_proj の空でない12チャートはすべて3次元で滑らか。
* **D_+(w) に制限するとアフィン版のフリップと厳密に一致。**

### A-3 の空振り2点

* **`singleDegreeIdeal` は今回も何もしなかった。** `y_1^2 y_5` と `y_1^2 y_4` が
  ともに次数3で、次数揃えが発動しない。射影版で効くはずという当初の見込みは外れた。
  → **後に次数の異なる例を作ったところ、この関数はバグだと判明した**（下記 B-8）。
* ~~**重み付き次数は現状では実用外。**~~ **B-3 で解消した。** 同じ環を
  `ℓ = (2,2,1)` で階数付けると `antiCanonicalSection` は `s = y_3^11` を返し
  `I^(1)` が次数30、`computeFlip` は17分で終わらなかった。`canonicalIdeal`
  経由なら I は次数2で 0.05 秒。現在は回帰テストに入っている。

### A-4 は完了: m > 1 を要求する例

`examples/toric-flip-index-two.m2`。`v4 = (1,3,-2)`、circuit 関係
`v1 + 3 v2 = 2 v3 + v4`。**m = 1 が却下され m = 2 で通る**ので、Step 4 のループが
初めて実際に回る例になった。

当初の候補だった `(1,1,-3)` は外れ。`(1,1,-a)` の族では常に T_+ 側（= K が π-ample
な側）が `<v2,v3,v4>, <v1,v3,v4>` で、これらの行列式は a によらず ±1 なので Z は
いつも滑らかで m = 1 で通ってしまう。**特異になるのは反対側**なので、K·C の符号が
逆になるよう重みを選ぶ必要がある。`v4 = (p,q,-r)` に対し circuit は
`p v1 + q v2 = r v3 + v4` で、壁 `<v3,v4>` での `K·C = -(p+q-r-1)`。したがって
`p+q-r > 1` かつ `r ≥ 2` に取ると Z = T_- 側になり、`<v1,v2,v4>` の行列式が -r で
特異になる。`(p,q,r) = (1,3,2)` がこれを満たす。

得られた知見:

* Z の特異点は指数 2（`<v1,v2,v4>` で `m·v1=m·v2=m·v4=1` を満たす m が `(1,1,3/2)`
  になる）。必要な m がちょうど 2 なのはこれで説明がつく。**B-2 の「特異点の指数から
  m の下限を見積もる」案を支持するデータ点**。
* m = 1 を却下しているのは**正規性ではなく small 判定**（m=1 でも Rees 代数は正規）。
  つまり「正規かつ small」の2条件は独立に効いている。

## 4. 次の作業 B: Algorithm 3 の精緻化

優先度順。

1. ~~**正規性判定**~~ **完了。R1 は判定不要だった。**

   **π が small なら Z は自動的に R1。** Z の余次元1の点は Exc(π)（余次元 ≥ 2）に
   入らないので π はそこで局所同型、よって局所環は X の余次元1の点の局所環 = DVR。
   したがって small を先に確認すれば、正規性は **S2 だけ**に帰着する。
   `isS2Source` を追加し、`computeFlip` は small → S2 の順にした。

   A-4 の例（m=1、変数9個、生成元22個、codim 5）の内訳:

   | 処理 | cpu time |
   |---|---|
   | `isSmallProjection` | 0.07 s |
   | `isNormal` の S2 部分 | **0.02 s** |
   | `isNormal` の R1 部分（`minors(5, jacobian)` が 1,436,495 生成元） | 119 s |
   | 同（`dim`） | 13 s |

   **当初の改良案はいずれも計測で否定された**ので記録しておく:
   * 「R1 を安価なフィルタとして先に弾く」→ R1 が高価な方。M2 の `isNormal` は
     既に安い S2 を先に回している。
   * 「チャート毎に `isNormal`」→ `u_i = 1` で斉次性が壊れ codim が 5→6 に上がり、
     minors が増える。同じ例で chart u_1 が 362 秒、u_2 が 322 秒（錐は 133 秒）。
   * 「イデアルが整閉 + 特異点が有理 ⟹ Rees 環が正規」→ 記憶にあった
     Lipman–Teissier / Huneke の結果は**2次元固有**で 3次元では成立しない。
     しかも I^(m) は divisorial なので整閉性は自動、X の有理性もトーリックなら
     自動で、いずれも情報を持たない。
   * 「`(I^(m))^k = I^(km)`（divisorial algebra が degree 1 生成）で代用」→
     1000倍速い（0.12 秒 vs 134 秒）が**強すぎる**。`Proj` は低次数の差を見ないので
     有効な m を誤って弾く。実例: (1,3,-2) の m=1 は degree-1 判定 false だが
     Rees 環は正規。速い accept パスとしてなら使える。

   さらに S2 も**錐ではなく Z の上で厳密に**判定するようにした。M2 の判定
   `codim Ext^j(A,S) ≥ j+2` が破れる軌跡は `Supp Ext^j` の余次元 ≤ j+1 の成分の
   和なので、**そのうち irrelevant ideal を含まないものが無いこと**を見れば
   ちょうど「Z が S2」になる（`isSmallProjection` と同じ「空集合を定める成分を
   捨てる」処理）。チャートも Veronese も不要。錐で見ると頂点軌跡
   `V(A_+) ≅ Spec R`（`Spec A` で余次元1）の分だけ過剰で、有効な m を弾きうる。

   | 例 | 錐 S2 | チャート S2 | **Z 上 S2** |
   |---|---|---|---|
   | アフィン ODP | 0.0010 s | 0.0068 s | 0.0003 s |
   | トーリック (1,1,−2) m=1 | 0.0011 s | 0.0089 s | 0.0003 s |
   | トーリック (1,3,−2) m=2 | 0.0080 s | 0.0152 s | 0.0003 s |
   | トーリック (1,3,−2) m=1 | 0.0189 s | 0.0919 s | 0.0002 s |
   | 射影 ODP | 0.0012 s | 0.0493 s（10チャート） | 0.0004 s |

   重みについて（ここでの重みは `deg x_j = (0,c_j)` の `c_j`、つまり基底 X が
   住む重み付き射影空間の重み。論文 Def 2.2 はファイバー側の重み `d_j` も許すが、
   Rees 構成は常に `d_j = 1` を与える）:

   * **十分性は重みに依らず成立**。`B = A_f` は `B' = B_0[f,f^{-1}]` 上有限で
     `B'` は `B'`-加群として `B` の直和因子、次元は一致するので
     `B` が S2 ⟹ `B_0 = A_(f)` が S2。
   * **必要性は「相対変数の重みがすべて1」のとき**（トーラスが自由に作用し
     `Spec A ∖ V(irr)` が Z 上の torsor になる）。アフィン基底と標準次数の
     射影基底はこれに該当し、Lemma 7.2 の条件そのものになる。
   * 重み付きでは十分条件のみ。ただし**健全性も停止性も損なわない**:
     十分 factorial な m では `(I^(m))^k = I^(km)` なので
     `A = ⊕_k O_X(-kmE)` は divisorial algebra ⟹ 正規 ⟹ 必ず判定が通る。
     加えて `isNormalSource ⟹ isS2Source` なので、従来より遅く止まることはない。
     失うのは最適性だけ（m を1つ余計に試しうる）。

   当初は重み付きで錐にフォールバックする実装だったが、上の十分性から
   **フォールバックは全面的に劣る**（同じ十分条件でありながら真に強く、遅い）
   ので削除し、分岐のない一様な実装にした。なお現時点で3つの判定が食い違う例は
   見つかっていない。
2. ~~**m の刻み**~~ **完了。MaxSteps! の約数を昇順に試す。**

   どの m で通っても答えは同じなので、重要なのは**小さい m を見つけること**。
   1反復のコストは m に対して急激に伸びる（`I^(m)` の生成元数 r が増え、Rees 環の
   変数まで増えるため）。`examples/toric-flip.m2` の3-fold で:

   | m | 1 | 2 | 3 | 4 | 6 | 8 | 12 |
   |---|---|---|---|---|---|---|---|
   | 1反復 | 0.02 s | 0.15 s | 0.17 s | 0.29 s | 0.87 s | 7.0 s | **>600 s** |

   そこで `multiplierSchedule` を追加し、既定を **`MaxSteps!` の約数の昇順**
   （既定 `MaxSteps = 4` なら `1,2,3,4,6,8,12,24`）にした。`1!,…,MaxSteps!` を
   含むので停止保証は不変。しかも**隙間を埋めるコストはほぼ無視できる** —
   `1,2,3,4,6,8` を全部試して 8.5秒、次の m=12 単独で 600秒超。逆に階乗だけだと、
   答えが m = 3, 4, 8 の3-fold で一気に m = 24 まで跳んでしまう。

   なお当初検討していた「特異点の指数から m の下限を先読みする」案は**不要になった**。
   小さい m から順に試すコストが無視できる以上、先読みの利得がない。A-4 で
   K_Z の指数 2 と必要な m = 2 が一致した観察は残るが、指数は出力側 Z の量で
   入力 X から求める手続きが未検討という問題も残ったままなので、追わない。
3. ~~**s の選択**（Step 2）~~ **完了。s を選ぶのをやめた。**

   Step 2 と Step 3 は合わせると「**ω_X を R のイデアルとして埋め込む**」ことに
   等しい（`I = O_X(K_X - div(s))` は ω_X と同型で、逆に ω_X と同型なイデアルは
   すべてこの形）。ならば s を経由せず、**最小次数の埋め込みを直接探せばよい**。
   `canonicalIdeal` を追加し、`Hom(ω_X, R)` の最小次数の生成元の像を取る。
   `flipDivisorData` の既定をこちらにし、`AntiCanonicalSection => s` で論文どおりの
   経路も残した。

   | 同一の3-fold | s 経由 | `canonicalIdeal` |
   |---|---|---|
   | `ℓ = (1,1,-1)` | `s = 1`、I は次数3 | I は次数1 |
   | `ℓ = (2,2,1)` | `s = y_3^11`、I は次数30、**17分で終わらず** | I は次数2、**0.05秒** |

   切り分けの結果、原因は**予想2つのうち後者**だった。`M = ∏ p_i^max(0,n_i)` を
   symbolic power の共通部分 `∩ p_i^(max(0,n_i))` に広げても生成元は変わらず
   （どちらも次数22が12個）、悪かったのは `Divisor` が返す K_X の代表元の方。
   重み付き次数では係数 11 の成分が出てしまう。なお射影版で余計な `y_1^2` が
   付いていたのも同じ現象で、これも解消した（アフィン版と同一の I になる）。

   残る自由度: 最小次数の埋め込みが複数あるとき、どれを取るかで I は変わり、
   必要な m も変わりうる。未検討。
4. ~~**symbolic power**~~ **完了。`SymbolicPowers` を使うのをやめた。**

   `intersect_i symbolicPower(p_i, m e_i)` は飽和が m と共に爆発する。`Divisor` の
   `ideal(mE)`（通常べきの積 + reflexive hull）に差し替えたら、結果は一致したまま
   ほぼ定数時間になった。`examples/toric-flip.m2` の3-fold で:

   | m | `intersect symbolicPower` | `Divisor` の `ideal(mE)` |
   |---|---|---|
   | 2 | 0.115 s | 0.005 s |
   | 4 | 0.212 s | 0.006 s |
   | 6 | 0.495 s | 0.006 s |
   | 8 | **3.247 s** | **0.007 s** |

   `SymbolicPowers` の Strategy 比較もしたが `UseMinimalPrimes => true` は
   むしろ遅い（m=8 で 5.2 秒）。「m を増やすとき前の結果を使い回す」案は、
   定数時間になったので不要。

5. **Rees イデアル**。現状は t を消去する自前実装（`bigradedReesIdeal`）。
   `ReesAlgebra` パッケージの `reesIdeal` を `flattenRing` 経由で双次数環に写す実装と
   速度比較をする。**優先度は低い** — 実測で m=8 でも 0.006 秒しかかかっていない。
6. **例外集合判定の高速化**。**当初の2案は実測で否定された。優先度は低い。**

   内訳の計測（`examples/toric-flip.m2` の3-fold）で、`minimalPrimes` が実質
   すべてであることは確認できた（m=8 で判定全体 1.08 秒のうち 1.00 秒。`trim`・
   次元計算・`eliminate` は合計 0.008 秒）。しかし提案されていた代替案は両方だめ:

   | m | `minimalPrimes` | saturate+dim（高速パス） | `topComponents`+decompose |
   |---|---|---|---|
   | 4 | 0.213 s | 0.040 s（発火せず） | 0.244 s |
   | 6 | 0.484 s | 0.016 s（発火せず） | 1.010 s |
   | 8 | 1.024 s | 0.031 s（発火せず） | **13.27 s** |

   * **equidimensional part（`topComponents`）は逆効果** — m=8 で13倍遅い。
   * **`codim` だけで済ませる案は構造的に不可能。** 「余次元1の relevant 成分が
     無ければ即 small」という高速パスは安価だが**原理的に発火しない**。§6 の
     論法 (2) のとおり `V(I O_Z)` は純余次元1なので、余次元1成分は常に存在する。
     必要なのは「その中に潰れるものがあるか」で、余次元だけでは答えられない。
   * Fitting イデアルで I の非局所単項軌跡を取る案も検討したが、A^3 の原点
     ブローアップのように「像の余次元は大きいが例外因子は余次元1」の場合を
     区別できないので使えない。

   仮に完全に解決しても1反復あたり最大15%の改善（m=8 で 7.0 秒中 1.08 秒）。
   B-2 で大きい m を踏む機会自体も減った。代替案が見えるまで着手しない。
8. ~~**`singleDegreeIdeal` の検証**~~ **完了。バグだった。修正済み。**

   一度も発火していなかったこの関数を検証するため、次数の異なる生成元を持つ
   `I^(m)` を作ったところ（重み付き次数なら容易に作れる）、**層が保存されていない**
   ことが判明した。8ケース中7ケースで飽和が一致しない。

   原因: `singleDegreeIdeal(J,D)` は実質 `Σ R_{D−d_i}·f_i` だが、重み付きでは
   **`R_{D−d_i} = 0` になりうる**（生成元が丸ごと落ちる）。`ℓ = (3,2,1)` の例では
   環の次数が {2,5,3,6,7} で `R_1 = 0`。D を大きくする案も不可 — 層を保つ D は
   まばらで**単調でもなく**（D=9 は通るが 10〜16 は通らない）、**存在しない場合もある**。

   実害: 同じ入力で **small 判定が反転**した（旧 false / 新 true）。間違った
   イデアルをブローアップしていたため。

   修正: 次数を揃えるのをやめ、**ファイバー方向に重みを付ける**
   （`deg u_i = (1, d_i − d_0)`、`deg t = (1, −d_0)`、`d_0 = min d_i`）。
   生成元の次数に関係なく双斉次になる。d_i がすべて等しいときは従来と完全に一致
   するので、既存の例・テストは無影響。`singleDegreeIdeal` と `UniformDegree` は
   論文の記述として残したが既定では使わない。

   代償: 重みが非自明なとき `b2mToGraphMorphism` が使えない（Lemma 2.3 の Segre
   構成はファイバー変数の双次数が (d_j, 0) であることを要求する）。明示的にエラー。

9. **`isS2Source` の大きい m での挙動**。B-4 で symbolic power が消えた結果、

## 6. 論文に照らして確認したい点

* **Step 3 の符号**。論文は `I := prod p_i^{n_i - m_i}` と書いているが、
  E = div(s) - K_X が有効因子なので O_X(K_X - div(s)) = O_X(-E) に対応する
  イデアルの指数は `m_i - n_i` になる。実装は後者。誤植かどうかの確認。
  トーリック例で実装の符号が正しい答え（K_Z が π-ample な側）を返すことは確認済み
  なので、論文側の誤植と見てよさそう。
* **Step 2 の s の存在**。トーリック例では K_X の係数がすべて負だったので
  `s = 1` になった。論文の記述では s は `prod p_i^max(0,n_i)` の元だが、
  この積が単位イデアルになる場合の扱いを明示しておきたい。
* **Step 5 の `V(h) ⊂ X × P^{r-1}`**。**要修正。** u_i の次数を (0,1) にすると、
  I^(m) の生成元の次数が揃っていないと Rees の関係式が双斉次にならない。
  かつて実装は I^(m) をその D 次成分で生成し直して回避しており、これは**重み付き
  射影空間では誤り**（B-8 参照）。正しくはファイバー方向に重みを付ける:

  ```
  deg u_i = (1, d_i - d_0),  deg x_j = (0, c_j),  deg t = (1, -d_0)
  ```

  （`d_i = deg f_i`, `d_0 = min d_i`）。これで生成元の次数に関係なく双斉次になり、
  d_i がすべて等しいときは論文の `deg u_i = (1,0)` に一致する。つまり論文の記述は
  「生成元の次数が揃う場合」の特殊形。**重み付き射影束 P(d) を使う形に直す**のが
  正しく、次数を揃える但し書きでは済まない。
* **Lemma 7.2 の正規性条件**。B-1 で分かったとおり、small を先に課せば R1 は
  自動なので、正規性の要求は実質 S2 だけ。論文でもこの順序で述べれば条件が
  一つ軽くなる。なお正規性を落として「正規化がフリップ」とする定式化も可能だが
  （small なら正規化も small、`J·O_W` は π-ample、`div(J·O_W) = mK_W` より
  K_W が π-ample）、MMP を正規多様体の枠組みで回したいので採らない。
* **十分 factorial なら正規性は自動**。「sufficiently factorial」は
  `(I^(m))^k = I^(km)` が成り立つように m を取ることなので、そのとき
  `A = ⊕_k O_X(-kmE)` は divisorial algebra で正規。つまり Lemma 7.2 の
  正規性は出力への追加制約ではなく、「十分 factorial な m に到達したか」を
  検出する条件、という位置づけになる。論文にこの一言を入れると、なぜ
  正規性を課すのかが読者に伝わりやすいのではないか。
* **Lemma 7.2 の適用**。**同値性は証明済み。残るのは論文の記述との突き合わせのみ。**
  実装は「V(I O_Z) の余次元1の既約成分で潰れるものが無い」を判定条件にしている。
  これが `codim Exc(π) ≥ 2` と同値であることの論法:

  1. `Exc(π) ⊆ V(I O_Z)`（I が可逆な所でブローアップは同型、I は `V(I)` の外で可逆）
  2. **`V(I O_Z)` は純余次元1** — `I·O_Z` はブローアップの構成から可逆、よって
     有効 Cartier 因子で Krull の単項イデアル定理が効く
  3. ゆえに `Exc(π)` の余次元1成分 D は `V(I O_Z)` に**含まれる**だけでなく
     その**成分そのもの**。D を含む成分 C は `dim C = dZ − 1 = dim D` なので C = D。
     ここが唯一注意を要する箇所で、(2) が閉じる鍵
  4. X 正規 + π 固有双有理 + ZMT より、`Exc` の成分は潰れるものに限り、逆も成立

  必要な仮定は「Z 既約・I ≠ 0・X 正規」だけで、いずれも前提から従う。
  なお (2) より**実装の次元判定は冗長**（relevant な成分は必ず次元 dZ−1）で、
  実質の判定は「潰れるか」のみ。安全網として残してある。

### 7-3. ビルドについて

固定しており、**`.tex` を触らずに再ビルドしてもバイト単位で同一**になる

ノートを実質的に改訂したときは Makefile の日付を上げる（PDF の作成日付になる）。

1回では収束しない。Makefile は2回走らせている。
